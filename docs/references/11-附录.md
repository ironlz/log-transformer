## 1. 配置文件完整示例

以下为基于递归 formatter 的完整端到端配置示例，对应文本格式：`#_#PS` 标记行 + CSV 数据 + `#_#FA` 标记行 + KV 数据，多个 phase 块混布在同一文件中。

```yaml
meta:
  version: "3.0"
  description: "半结构化 phase 数据文件解析配置（统一节点图 / 类型无关 DSL 示例）"

input:
  path: "/data/phase_data_20261001.dat"
  encoding: "utf-8"
  filename_node: __filename__      # 文件名虚拟块绑定到 nodes 中的同名 source 节点

# configs：外置的实现特有配置片段，对 DSL 不透明，节点用 config_ref 引用；
# DSL 不解析其中的 pattern/delimiter/separator/marker 等字段，实例化时原样注入实现。
configs:
  filename_date:
    pattern: "phase_data_(?P<date>\\d{8})\\.dat"
  marker_phase_split:
    marker: "^#_#PS:"
    include_marker: true
  regex_ps_meta:
    pattern: "^#_#PS:(?P<phase_id>[^,]+),(?P<seq>\\d+),(?P<batch>[\\d_]+)"
  csv_space:
    delimiter: " "
    has_header: true
  regex_fa_meta:
    pattern: "^#_#FA:(?P<field_names>[^:]+):(?P<indices>[\\d,]+)"
  kv_phase:
    kv_separator: ":"
    field_separator: ","
  enrich_cfg:
    join_key: "ps_csv.phase_id = ps.phase_id"
  aggregate_cfg:
    group_by: "enriched.phase_id"
    aggregations:
      - "count(*) as csv_record_count"
      - "max(enriched.test_time) as latest_test_time"

# nodes：统一节点图。节点只描述拓扑角色(kind)、实现绑定(impl)、关系(children/inputs)、
# 输出契约(output)、上下文契约(context)，不含任何解析器/算子的具体类型与特有配置。
nodes:
  # 文件名虚拟块（source）
  - id: __filename__
    kind: source
    impl: regex_extract
    config_ref: filename_date
    output: {namespace: "file.", schema: [date]}

  # phase 容器（结构节点：把文件解析成 phase 块实例，建立 phase_id 上下文）
  - id: phase_block
    kind: container
    impl: marker_block_split
    config_ref: marker_phase_split
    context: {id_field: phase_id}   # 注入上下文键 phase_block.phase_id
    children:
      - id: ps_meta
        kind: source
        impl: regex_extract
        config_ref: regex_ps_meta
        output: {namespace: "ps.", schema: [phase_id, seq, batch]}
      - id: ps_csv
        kind: source
        impl: csv_extract
        config_ref: csv_space
        output: {namespace: "ps_csv.", schema: [phase_id, test_time]}
      - id: fa_meta
        kind: source
        impl: regex_extract
        config_ref: regex_fa_meta
        output: {namespace: "fa.", schema: [field_names, indices]}
      - id: fa_kv
        kind: source
        impl: kv_extract
        config_ref: kv_phase
        output: {namespace: "fa_kv."}   # 无 schema：开放键空间，仅可被前缀引用

  # 算子（process）：特有计算配置经 config_ref 不透明引用
  - id: enrich_csv_with_fa
    kind: process
    impl: enrich_join
    config_ref: enrich_cfg
    inputs:
      - {from: ps_csv,  select: {key_prefix: "ps_csv."}}
      - {from: fa_meta, select: {keys: ["fa.field_names", "fa.indices"]}}
      - {from: ps_meta, select: {keys: ["ps.phase_id", "ps.seq"]}}
    output: {namespace: "enriched.", schema: [phase_id, test_time, seq]}

  - id: aggregate_phase
    kind: process
    impl: group_aggregate
    config_ref: aggregate_cfg
    inputs:
      - {from: enrich_csv_with_fa, select: {key_prefix: "enriched."}}
      - {from: fa_kv, select: {key_prefix: "fa_kv."}}
    output: {namespace: "phase_stats.", schema: [phase_id, csv_record_count, latest_test_time]}

# runtime：框架级运行参数，DSL 持有/透传，不做类型相关解释
runtime:
  max_block_queue_mb: 256
  max_kv_queue_mb: 128
  spill_threshold_mb: 512
  max_heap_mb: 4096
  parallelism: auto
  read_buffer_mb: 256
  storage_medium: auto
  temp_dir: "/data/tmp"
  projection_enabled: true
  marker_search_prefix: "#_#"
  output:
    path: "/data/output/result_20261001.jsonl"
    format: jsonl
    compression: gzip
```

## 2. 解析器 / 算子开发指南

开发者不直接实现完整接口、也不自行拼键：解析器继承 `BaseParser` 实现 `extract` 钩子，算子继承 `BaseOperator` 实现 `compute` 钩子；前缀拼接、上下文注入/传播、投影、短名还原、KVSet 组装、spill 均由抽象基类统一完成（见 `../design/键生成规则与数据约束.md`、`../design/04`、`../design/05`）。

### 2.1 解析器开发（BaseParser 子类）

| 要求 | 说明 |
| --- | --- |
| 实现 extract(block) | 只从字节得到 field_name→value（或记录集）；不拼键、不加前缀、不注入上下文 |
| 声明输出契约 | output.namespace + schema；产出键受契约约束，未声明字段不进入下游 |
| 注册实现 | 将实现以 impl id 注册到 ImplementationRegistry，供 DSL 节点 `impl` 绑定 |

### 2.2 算子开发（BaseOperator 子类）

| 要求 | 说明 |
| --- | --- |
| 实现 compute(short_inputs, context) | 输入已投影、已去前缀、按短名组织；只返回输出字段短名→value |
| 流式处理 | 必须支持逐条消费输入，不要求全量加载 |
| 输出契约 | output.namespace + schema；大结果必须支持 spill（由基类处理） |
| 资源释放 | 释放逻辑挂接 release_hook，必须幂等 |
| 注册实现 | 以 impl id 注册，供 DSL 节点 `impl` 绑定 |

其他约定：

- **特有配置不透明**：实现特有参数由 DSL 的 config/config_ref 原样注入，框架不解析；实现自身按其 schema 校验。
- **内存约束**：实现内部不得持有超过 spill_threshold 的数据，超阈值由基类 spill。
- **测试要点**：单元测试覆盖正常路径、空输入、超大输入、错误输入、并发调用。

> 解析器/算子生命周期与 [04-递归分块解析引擎.md](../design/04-递归分块解析引擎.md)、[05-算子执行模型.md](../design/05-算子执行模型.md) 一致。

## 3. 常见数据流场景（统一节点图）

> 以下场景均用统一节点（kind=container/source/process）+ impl 绑定表达；结构关系用 children，数据依赖用 inputs，块实例身份用 context。

### 3.1 场景一：末尾依赖（所有处理依赖尾部的维表块）

- nodes 中定义尾部维表块：container 用相应分块 impl，内含 source 叶子。
- 所有 process 的 inputs 直接或间接引用该维表 source。
- 系统识别末尾依赖，第二遍优先加载维表并构建 lookup 索引，随后流式处理其他块，维表输出缓存复用不重读。
- runtime.spill_threshold_mb 按维表投影后大小调整，投影小可放内存。

### 3.2 场景二：多块关联（事件块关联用户块和设备维表）

- nodes 定义三种一级 container（用户块、事件块、维表块），各绑定分块 impl 并含 source 叶子。
- enrich 类型 process 的 inputs 引用事件块 + 维表块 source，aggregate 引用用户块 + enrich 输出。
- 波次 0：用户块、维表块优先加载解析并缓存，事件块随后加载；波次 1：enrich；波次 2：aggregate。
- runtime.projection_enabled 必须开启，只加载 join 需要的字段。

### 3.3 场景三：标记行 + 数据块交替（PS/CSV/FA/KV 混布）

- phase_block 为 container，impl 绑定标记分块实现（marker 等特有配置在 configs 中，不进 DSL）。
- children 依次为 ps_meta、ps_csv、fa_meta、fa_kv 四个 source，各自绑定字段解析 impl。
- 每个 phase 块内部结构固定，子块按 children 顺序依次消费。
- container 的 context 声明 phase_id 身份字段，子块输出自动携带 phase_block.phase_id 上下文。

### 3.4 场景四：纯流式无依赖（各块独立解析，无跨块依赖）

- 所有 process 无跨块依赖，每条链路独立。
- 系统最大化并行度，NVMe 上可满带宽并行处理。
- 无依赖块需优先加载，索引扫描后直接进入数据加载与处理，所有 source 并行解析。
- 内存占用最低（无维表数据），处理速度最快。
