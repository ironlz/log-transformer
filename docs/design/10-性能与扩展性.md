# 10 · 性能与扩展性

> 所属项目：可配置化超大文件数据解析服务
> 文档类型：模块详细设计（性能与扩展性）
> 上游依据：[01-总体设计.md](01-总体设计.md)（设计目标）、[06-依赖分析与并行调度.md](06-依赖分析与并行调度.md)、[07-大文件内存管理.md](07-大文件内存管理.md)

本文档定义时间复杂度分析、空间复杂度分析、并行度扩展、存储介质适配。

---

## 1. 时间复杂度分析

| 环节 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 配置加载与 DAG 构建 | O(O) | O = 算子数量，常数级，不涉及文件 |
| 索引扫描（第一遍读） | O(N) | N = 文件大小，一次顺序遍历，与文件大小线性相关 |
| 数据加载与处理（第二遍读） | O(K + P) | K = 实际需要读取的 Block 总大小（K ≤ N，每块只读一次），P = 解析出的 KV 总数 |
| KV 解析 | O(P) | P = 解析出的 KV 总数，P 与 N 线性相关，已包含在数据加载阶段中 |
| 算子执行 | O(P × C) | C = 平均算子复杂度（通常为常数，如 hash lookup） |
| 总时间 | O(N + P) | 随文件大小线性增长，无指数增长环节；逻辑读取两遍，物理 IO 因 mmap 可能更少 |

**系统严格禁止以下指数增长操作：**

- **全量排序**：改用外部排序，复杂度 O(N log N) 但分块执行。
- **笛卡尔积**：join 必须有 join_key。
- **嵌套循环**：必须用 hash 或 merge join。

任何算子实现若引入超线性复杂度，需在配置中显式声明并接受性能降级。

## 2. 空间复杂度分析

| 数据结构 | 空间复杂度 | 存储位置 |
| --- | --- | --- |
| Block 索引表 | O(B) | B = Block 数量，通常 MB 级，内存 |
| 有界队列 | O(1) | 常量上限，与文件大小无关，内存 |
| 依赖维表 | O(D) | D = 投影后的依赖数据量，有配置上限，内存或磁盘 |
| 当前处理批次 | O(1) | 常量上限，内存 |
| Spill 文件 | O(P) | P = KV 总数，但在磁盘上，不占内存 |
| DAG 状态 | O(O) | O = 算子数量，常数级，内存 |
| 峰值内存 | O(1) | 常量，可配置硬上限，与文件大小无关 |

## 3. 并行度扩展

- **链路级并行**：DAG 中独立链路的数量决定最大并行度，由配置的算子依赖关系决定。
- **块级并行**：同一链路内无依赖的多个 Block 可并行解析（如波次 0 的所有 SourceNode）。
- **算子级并行**：无状态算子（如 transform、filter）可对 KV 批次做数据并行处理。
- **扩展上限**：受存储介质 IO 带宽（HDD 约 150MB/s，NVMe 约 3~7GB/s）和 CPU 核数限制。
- 并行度可通过配置调整，也可设为 auto 由系统根据环境自动计算最优值。

---

## 4. 存储介质适配

| 存储介质 | 并行读策略 | 随机读策略 | 推荐并行度 |
| --- | --- | --- | --- |
| HDD | 强制单线程顺序读，禁用并行随机读 | 按 offset 排序后转化为跳跃式顺序读 | 1 |
| SATA SSD | 2~4 路并行读，随机读可接受 | 直接随机读，适度排序优化 | 2~4 |
| NVMe SSD | 4~8 路并行读，充分利用并行 IO 能力 | 直接随机读，NVMe 并行处理能力强 | 4~8 |

`storage_medium` 配置项设为 auto 时，系统通过磁盘类型探测自动选择策略。**HDD 场景下即使 DAG 有多条独立链路，也强制串行执行**以避免磁头颠簸导致的性能灾难。

> 并行度控制（HDD 单链路、NVMe 4~8 路）与 [06-依赖分析与并行调度.md](06-依赖分析与并行调度.md) 一致。
