本文档定义依赖分析与并行调度：DAG 构建、拓扑排序与波次划分、串行依赖识别、并行链路生成、链路数据最小化持有策略、调度器实现。

---

## 1. DAG 构建：从配置到依赖图

DAG 构建在配置加载阶段完成，**不读取文件**，是纯静态分析：

- **节点集合**：所有 source 节点（nodes 图中的叶子，即 KV 产出点）+ 所有 process 节点（算子）；container 节点只承载结构，不进入数据流 DAG。
- **边推导**：遍历每个 process 的 inputs，为每个 `from` 引用创建一条数据流边；children 为结构边，不构成数据依赖。
- **环检测**：使用 DFS 检测依赖环，存在环时配置校验失败并报错。
- **节点标注**：每个节点标注入度、出度、消费者列表、投影字段集合。

---

## 2. 拓扑排序与波次划分

使用 **Kahn 算法**进行拓扑排序，并按入度分层（波次）：

- **波次 0**：所有 SourceNode（入度为 0 的根节点），可完全并行加载和解析。
- **波次 1**：只依赖波次 0 输出的算子，波次 0 全部完成后可并行执行。
- **波次 N**：依赖前序波次输出的算子，依次类推。

约束：

- 同一波次内的节点**无相互依赖**，可完全并行执行。
- 波次之间**必须串行**：上一波次全部完成后，下一波次才能开始。

> 波次划分是算子执行层面的拓扑语义；在执行阶段（阶段三）中，SourceNode 的解析还按「依赖块优先、非依赖块随后」的顺序细分，两者不冲突——依赖块与算子波次的关系详见 [08-执行流程详解.md](08-执行流程详解.md)。

## 3. 串行依赖识别

| 依赖类型 | 判定规则 | 执行约束 |
| --- | --- | --- |
| 严格串行 | 算子 B 的所有输入都来自算子 A 的输出（A 是 B 的唯一上游） | A 完成后 B 才能开始，不可并行 |
| 共享依赖 | 算子 B 和 C 都依赖算子 A 的输出，但 B 和 C 互不依赖 | A 先完成，B 和 C 可并行 |
| 传递依赖 | A → B → C，C 间接依赖 A（通过 B） | A、B、C 依次串行，不可重排 |
| 独立分支 | 算子 B 和 C 分别依赖不同的上游，无任何共享依赖 | B 和 C 完全并行，互不影响 |

## 4. 并行链路生成

从 DAG 的根节点出发，通过深度优先搜索（DFS）遍历所有到叶子节点的路径，每条路径构成一条 Pipeline（处理链路）。链路生成算法包含以下优化：

| 优化 | 说明 |
| --- | --- |
| 链路合并 | 如果两条链路共享大量前缀节点（如共享同一个 formatter 叶子节点），合并为一条链路，减少重复解析 |
| 链路拆分 | 如果一条链路在某个节点后分出多个独立分支，拆分为多条子链路，各分支并行执行 |
| 依赖聚合 | 被多条链路共享的维表节点（如块 D）只执行一次，结果广播给所有引用它的链路 |
| 链路排序 | 按预计处理量排序，大链路优先启动以均衡总执行时间（LPT 调度算法） |

---

## 5. 链路数据最小化持有策略

这是避免内存爆炸的关键策略，确保每条链路只持有最低限度的数据：

| 策略 | 说明 |
| --- | --- |
| 投影下推 | 每条链路执行前计算所需字段的最小集合（基于算子的 key 选择器），解析时只提取这些字段，未引用字段直接丢弃 |
| 及时释放 | 算子输出被所有下游消费者消费后，调度器立即调用 release()，释放内存或删除 spill 文件 |
| 波次间回收 | 每波次完成后，全局扫描所有节点输出，释放已被完全消费的 KVSet |
| 生命周期标注 | 每个 KVSet 标注消费者列表和消费状态，最后一个消费者完成后触发自动释放 |
| 流式传递 | 算子间通过有界队列流式传递 KV，不物化全量中间结果 |
| 维表共享 | 被多链路共享的维表数据只存一份，引用计数管理，最后一个引用释放后才回收 |

## 6. 调度器实现

调度器采用**事件驱动模型**，维护四个集合：就绪队列（READY）、执行中集合（RUNNING）、已完成集合（COMPLETED）、等待依赖集合（WAITING）。

| 机制 | 说明 |
| --- | --- |
| 节点完成事件 | 节点执行完成后触发，检查其所有下游节点的输入是否全部就绪，就绪则移入 READY |
| 并行度控制 | 根据 storage_medium 和 CPU 核数动态调整并发执行的链路数。HDD 强制单链路顺序执行，NVMe 支持 4~8 路并行 |
| 背压机制 | 下游 KV 队列满时，上游解析线程自动阻塞，避免队列无限堆积 |
| 容错处理 | 节点执行失败时，根据配置决定重试（指数退避，最多 N 次）或终止整个链路 |
| 进度追踪 | 实时记录每条链路的处理进度（已处理 Block 数、已产出 KV 数、当前算子） |
