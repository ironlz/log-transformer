# 08 · 执行流程详解

> 所属项目：可配置化超大文件数据解析服务
> 文档类型：模块详细设计（执行流程）
> 上游依据：[01-总体设计.md](01-总体设计.md)（四阶段）、[06-依赖分析与并行调度.md](06-依赖分析与并行调度.md)、[07-大文件内存管理.md](07-大文件内存管理.md)
> 下游关联：[09-错误处理与可观测性.md](09-错误处理与可观测性.md)

本文档详解四个执行阶段：配置加载与 DAG 构建、索引扫描（第一遍读）、数据加载与处理（第二遍读，每块只读一次）、结果输出与清理。

---

## 1. 阶段一：配置加载与 DAG 构建

本阶段**不读取文件**，纯内存操作，耗时通常 < 1 秒：

1. 读取并校验 YAML 配置（语法校验 + 语义校验 + 环检测）。
2. 构建算子 DAG，标注节点依赖关系和投影字段集合。
3. 拓扑排序，划分执行波次。
4. 生成并行处理链路列表，计算每条链路的投影字段最小集合。
5. 识别依赖块：遍历 DAG，标记被其他算子引用的 SourceNode（如维表块），这些块在第二遍中需优先加载。
6. 根据 storage_medium 和 parallelism 配置确定调度策略。

**产出**：执行计划（DAG + Pipeline 列表 + 投影映射表 + 依赖块标记）。

---

## 2. 阶段二：索引扫描（第一遍读文件）

1. 大缓冲顺序读文件（默认 256MB buffer），扫描一级分隔符。
2. 匹配到块边界时记录 BlockMeta（blockId, offset, size, level）。
3. 文件名包装为虚拟 Block，注入索引表首位。
4. 根据配置的 includes/excludes 过滤不需要的 Block（不记录索引）。
5. 根据阶段一的依赖块标记，在索引表中标注哪些块是依赖块（需优先加载）。
6. 索引表回填到 DAG 的 SourceNode，完成物理执行计划。

**性能**：约等于磁盘顺序读上限。统一口径如下（与 [04-递归分块解析引擎.md](04-递归分块解析引擎.md) 一致）：

| 介质 | 80GB 索引扫描耗时 |
| --- | --- |
| NVMe | 15~30 秒 |
| SATA SSD | 约 2.5 分钟 |
| HDD | 约 9 分钟 |

内存仅读缓冲（256MB）。

---

## 3. 阶段三：数据加载与处理（第二遍读文件，每块只读一次）

这是核心执行阶段。源文件通过 mmap 映射到虚拟地址空间，调度器按 DAG 拓扑顺序加载块，**每个块在本阶段只被读取和解析一次**。依赖块优先加载，其完整 KVSet 被缓存，供后续算子复用，避免重复读取。

### 3.1 子步骤一：依赖块优先加载与维表构建

1. 调度器从索引表中取出标记为依赖块的 SourceNode，按 offset 排序。
2. 通过 mmap 区域加载依赖块（零拷贝），执行多级分块和 KV 解析。
3. 依赖块的完整 KVSet 缓存到内存或 spill 到磁盘（取决于大小），供后续链路直接复用。
4. 同时从完整 KVSet 中提取投影字段，构建维表索引（hash 表或排序文件），供关联/连接类算子快速 lookup。
5. 若依赖块在文件尾部（末尾依赖场景），直接通过 mmap 访问尾部区域，无需 seek 开销。

### 3.2 子步骤二：其他块加载与并行链路执行

依赖块就绪后，调度器按波次启动处理链路，加载非依赖块：

- **波次 0**：非依赖 SourceNode 并行加载和解析（受存储介质并行度限制），产出基础 KVSet。
- **波次 1**：只依赖波次 0 输出的算子并行执行，消费上游 KV，产出衍生 KV。
- **波次 N**：依次执行，直到所有波次完成。
- 每条链路内部：加载 Block → 多级分块 → KV 提取 → 算子链串行执行。
- 依赖块的 KVSet 从缓存中直接获取，**不重新读取源文件、不重新解析**。
- KV 通过有界队列流式传递，超阈值自动 spill to disk。
- 算子输出被所有下游消费后立即释放，波次间全局回收已消费数据。
- 最终 KV 写入输出目标（文件/消息队列/数据库）。

**读取次数保证**：每个源文件块在本阶段只被 mmap 访问和解析一次。依赖块的解析结果被缓存复用，非依赖块解析后即处理即释放。逻辑上源文件总共被读取两遍（索引扫描 + 数据加载），物理 IO 因 mmap page cache 可能更少。

> 波次语义与依赖块的细分顺序，与 [06-依赖分析与并行调度.md](06-依赖分析与并行调度.md) 互补：波次描述算子执行的拓扑依赖；依赖块优先加载是对 SourceNode 解析顺序的执行层优化。

---

## 4. 阶段四：结果输出与清理

1. 所有链路完成后，将最终 KV 按配置格式序列化写入输出目标。
2. 清理所有 spill 临时文件和依赖维表的磁盘文件。
3. unmap 所有 mmap 区域，释放虚拟地址空间。
4. 输出执行统计报告：各阶段耗时、总 IO 量、逻辑读取次数、物理 IO 估算、内存峰值、KV 总数、错误数、处理速率。
