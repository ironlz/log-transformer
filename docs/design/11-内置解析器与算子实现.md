# 11 · 内置解析器与算子实现（实现库 / 扩展指南）

> 所属项目：可配置化超大文件数据解析服务
> 文档类型：设计类（**内置实现库**，非核心框架）
> 上游依据：[01-总体设计.md](01-总体设计.md)、[03-配置驱动DSL设计.md](03-配置驱动DSL设计.md)、[04-递归分块解析引擎.md](04-递归分块解析引擎.md)、[05-算子执行模型.md](05-算子执行模型.md)、[键生成规则与数据约束.md](键生成规则与数据约束.md)

## 1. 实现总览与注册模型

实现分三类，分别对应节点 kind：

| 实现类别 | 基类（核心定义） | 节点 kind | 职责 |
| --- | --- | --- | --- |
| 容器解析器 | `BaseContainerParser` | container | 把父区域切成子块、解析实例身份、递归调度 |
| 叶子解析器 | `BaseParser` | source | 从块字节提取字段短名（成键由基类完成） |
| 算子 | `BaseOperator` | process | 从短名输入计算输出字段短名 |

### 1.1 每个实现的描述维度

- **impl id**：注册中心唯一标识，DSL 节点 `impl` 引用它。
- **不透明 config schema**：该实现特有参数的结构；由实现自身校验，框架与 GraphValidator 不解析其内部。
- **行为**：extract/compute 钩子做什么。
- **字段名来源 / 输出字段**：产出字段短名从何而来、静态或动态、输出字段规则。

> **命名空间不属于实现配置**：输出命名空间由节点 `output.namespace` 提供，impl config 不携带前缀。同一实现可被不同节点复用于不同命名空间。

### 1.2 注册与装配

- 注册：`ImplementationRegistry.register(impl_id, factory, config_schema, output_contract_hint)`。
- 装配：Assembler 对节点按 `impl` 取 factory，把该节点 config（含 config_ref 浅合并结果）传入创建实例。
- 特有 config 校验失败由实现抛出配置错误，定位到节点 id 与字段。

## 2. 容器解析器与分块端口实现

容器解析器由三个端口组合而成。本节列出随系统交付的容器解析器与各端口内置实现。

### 2.1 内置容器解析器

| impl id | 行为 | 典型不透明 config（示意，由实现自校验） |
| --- | --- | --- |
| `marker_block_split` | 按起始标记行切分同级实例；逐实例解析身份并压栈，按调度策略递归子节点 | 实例起始标记 pattern、是否含标记行、子块调度方式、身份解析规则 |

> 该实现用于 phase_block 这类"标记行 + 数据块"容器。其他分块范式（纯分隔符、定长记录等）可由复用第 2.2~2.4 端口的容器实现提供。

### 2.2 BoundaryMatcher 内置实现（7 种边界）

无状态纯函数，在父区域内确定范围：

| 边界实现 | 匹配逻辑 | 结束条件 | 关键 config |
| --- | --- | --- | --- |
| start_marker | 扫描首个匹配 marker 正则的行首 | 下一个同级 start_marker 行首或父区域结束 | marker、include_marker |
| single_line | 起始行匹配 match 正则则块为该行 | 行尾 | match |
| until_next_marker | 扫描直到匹配 next_marker 的行 | next_marker 行的前一行末尾 | next_marker |
| until_block_end | 从当前位置到父区域结束 | 父区域结束偏移 | 无 |
| delimiter | 扫描找到 delimiter 字节序列 | delimiter 起始（trim 时不含 delimiter） | delimiter、trim |
| fixed_length | 从起始位置取固定长度 | 起始 + length | length |
| eof | 从当前位置到文件结束 | 文件大小 | 无 |

正则行首锚定（`^`）避免误匹配内容中的相同串；匹配在 mmap 区域上执行，不复制数据。

### 2.3 BlockIdResolver 内置实现（4 种来源）

| 来源实现 | 行为 | 关键 config | 失败处理 |
| --- | --- | --- | --- |
| marker_line | 从标记行配合 regex 捕获组提取身份 | pattern、capture_group | 未命中 → fallback sequence |
| content_regex | 从块内容任意位置正则提取 | pattern、capture_group | 未命中 → fallback sequence |
| sequence | 按出现顺序编号 | prefix（如 `phase_`） | 恒成功 |
| fixed | 固定值，同类型实例共享 | value | 恒成功 |

解析在第一遍 scan 中同步完成，不需第二遍读取。

### 2.4 DispatchStrategy 内置实现

| 实现 | 行为 | 适用 |
| --- | --- | --- |
| sequential | 按 children 声明顺序依次消费父区域，维护当前偏移 | 块内子块顺序固定（多数格式），默认 |
| marker_driven | 扫描时按匹配到的标记动态确定子块归属，维护"当前数据归属"状态 | 子块顺序不固定、多标记混布 |

## 3. 叶子解析器内置实现

字段名静态/动态判定与静态推演规则以 [键生成规则与数据约束.md](键生成规则与数据约束.md) §3 为准；本表给出 impl id、特有 config 与 extract 行为。

| impl id | 解析器 | 不透明 config 关键字段 | extract 行为 / 字段短名来源 | 静态/动态 |
| --- | --- | --- | --- | --- |
| `regex_extract` | regex | pattern | 取正则命名捕获组名为字段短名 | 静态 |
| `fixed_width_extract` | fixed_width | fields[{name,offset,length,type}] | 按 fields 切分，name 为短名 | 静态 |
| `json_path_extract` | json_path | paths、可选别名 | 别名优先，否则取 path 末段 | 静态 |
| `csv_extract` | csv / tsv | delimiter、has_header、quote_char | has_header=false：位置名 `col_{n}`；has_header=true：表头单元格文本（净化） | 无表头静态 / 有表头**动态** |
| `kv_pair_extract` | kv_pair | kv_separator、field_separator | 左值键名（净化）为短名 | **动态** |
| `kv_multi_extract` | kv_multi | kv_separator、field_separator | 数据中键名 token（净化） | **动态** |
| `line_fields_extract` | line_fields | line_separator | 每行行首字段名 token | **动态** |
| （用户注册） | custom | plugin、任意 config | 插件产出；**必须声明输出字段 schema** | 默认动态 |

> tsv 是 csv 以制表符为 delimiter 的特例，由 `csv_extract` 经 config 覆盖实现，不单独占 impl id。

### 3.1 动态解析器的键空间约束（key_schema）

动态解析器在其不透明 config 中声明 `key_schema`，把开放键空间收敛为可推演键空间：

| config 字段 | 语义 |
| --- | --- |
| key_schema.fields | 已知字段短名集合，用于静态推演与精确引用校验 |
| key_schema.on_unknown = error / drop / keep（默认 keep） | 数据出现 fields 之外键：报错 / 丢弃 / 保留 |
| key_schema.pattern（替代 fields） | 只约束字段名形态，不能枚举精确键，下游仍须前缀/正则 |

规则与三种下游写法、数据推演见 [键生成规则与数据约束.md](键生成规则与数据约束.md) §4。

### 3.2 块内多行

叶子在一个块内产出多行（csv、line_fields）时，默认以记录集承载（列名静态、面向集合算子按列短名迭代）；config 中 explode_records=true 时展开为 `{row_index}.{column}`，行号用保留字段 `__row__`。见键文档 §6.2。

## 4. 算子内置实现

输出字段规则以 [键生成规则与数据约束.md](键生成规则与数据约束.md) §5.4 为准；本表给出 impl id、特有 config 与 compute 行为。

| impl id | 算子 | 不透明 config 关键字段 | compute 行为 | 输出字段短名规则 |
| --- | --- | --- | --- | --- |
| `enrich_join` | enrich | join_key | 用维表对主流做 lookup join，补维度字段 | 主流投影短名 + 维表字段别名；join_key 不重复产出 |
| `group_aggregate` | aggregate | group_by、aggregations(`... as alias`) | 按分组字段分组做 count/sum/avg/max/min | 分组字段短名 + 聚合别名 |
| `map_transform` | transform | 映射/表达式（`as`） | 重命名、类型转换、表达式衍生 | 显式声明名字；未声明字段默认丢弃 |
| `predicate_filter` | filter | predicate | 按条件保留/分流 | 投影输入短名透传 |
| `hash_or_merge_join` | hash/merge join | join_key、select | 两侧按 join_key 做 hash 或 merge join | 显式 select；缺省带侧别前缀 `l_*`/`r_*` 防碰撞 |
| `key_deduplicate` | deduplicate | keys、keep(first/last) | 按 key 去重保留首/末次 | 投影输入短名透传 |
| （用户注册） | custom | 任意 config | 插件计算 | **必须声明输出字段 schema** |

### 4.1 输出碰撞与别名

- 多个输入短名相同且都要输出 → 必须显式别名，否则触发 KEY-E4（算子输出碰撞）。
- enrich 主流与维表同名字段都要输出时同样必须别名。
- 数据键在算子边界统一重新挂到本节点 output.namespace；上下文键取输入并集原样传播。

### 4.2 输出键数据推演（摘要）

- enrich：给定主流短名 phase_id、test_time，维表关联字段 seq，namespace=`enriched.` → `enriched.phase_id`、`enriched.test_time`、`enriched.seq`。
- aggregate：group_by 短名 phase_id，聚合别名 csv_record_count、latest_test_time，namespace=`phase_stats.` → `phase_stats.phase_id`、`phase_stats.csv_record_count`、`phase_stats.latest_test_time`。
- 完整推演见键文档 §5.5、§5.6、§8。

## 5. 扩展指南：新增解析器 / 算子

### 5.1 新增叶子解析器

1. 继承 `BaseParser`。
2. 实现 `extract(block) -> ParseResult`：只产出 field 短名 -> value（或记录集）；不拼键、不加前缀、不注入上下文。
3. 定义该实现的不透明 config schema，并在实现内做校验。
4. 字段空间动态时，在 config 中支持 key_schema；custom 必须能声明输出字段 schema。
5. 以 impl id 注册 factory + config schema。
6. 测试：正常路径、空块、超大块（触发 spill）、格式错误、并发调用。

### 5.2 新增容器解析器 / 端口实现

1. 容器继承 `BaseContainerParser`；可复用或新提供 BoundaryMatcher / BlockIdResolver / DispatchStrategy。
2. 新端口实现为无状态/可装配组件，定义 config schema。
3. 以 impl id 注册容器；端口实现按装配约定注册。
4. 测试：多标记、嵌套递归、边界越界、身份解析失败 fallback、块尾结束。

### 5.3 新增算子

1. 继承 `BaseOperator`。
2. 实现 `compute(short_inputs, context) -> ComputeResult`：只返回输出字段短名 -> value；不碰前缀、上下文传播、KVSet 组装。
3. 定义不透明 config schema 并自校验；声明输出字段（custom 必须声明 schema）。
4. 以 impl id 注册。
5. 测试：流式逐条、空输入、超大输入（spill）、字段缺失、类型错误、并发、release 幂等。

### 5.4 实现必须遵守的约束

| 约束 | 要求 |
| --- | --- |
| 不自行成键 | 不直接字符串拼键；成键/短名/上下文全部经 KeyComposer 与基类 |
| 有界内存 | 内部状态不得超过 spill_threshold；超阈值由基类 spill，不自行管理落盘 |
| 流式处理 | 不得要求全量输入驻留 |
| 错误通道 | 可恢复/不可恢复错误经统一错误通道（09），不自行决定重试 |
| 资源释放 | 释放挂接 release_hook，必须幂等 |
| 系统保留名 | 不产出以 `__` 开头的字段（`__filename__`、`__row__` 等为系统保留） |
